## Summary

Build a new AI driver MCP, separate from `tools/live_probe_mcp` and the volatile live bridge. It provides stable observations and input-like actions, plus proven test setup commands for launching matches, entering towns/combat, and granting resources/law points.

It must not expose shortcuts, fallbacks, arbitrary reflection, volatile mutation, compiled probes, or generic field writes.

## Non-Negotiable Rules

- No shortcut APIs. If a needed route is unproven, the agent must prove it before exposing it.
- No executable temporary or unproven commands. Unproven work may appear only in docs or backlog, not as callable MCP tools.
- No fallback behavior. Each command has one documented route; if route validation fails, it returns a structured failure and does nothing.
- No volatile bridge reuse inside the AI MCP. Existing diagnostic tools may be used during development to prove routes, but never wrapped as AI MCP behavior.
- No coordinate guessing for `ai_act`. `ai_act` can only execute actions emitted by a fresh `ai_observe`. Sibling `pilot_click` accepts explicit screen coordinates for human-parity UI clicks and fails closed when no UI target is under the point.
- No stale actions. Every `ai_act` requires `observationId`, `screenId`, and target fingerprint revalidation.
- No release leakage. Release-candidate build and package validation must prove AI driver code is excluded.
- MCP-level unproven-command rejection remains required (`ai_open_town`, `ai_start_combat`, `pilot_drag` absent). Smoke/static checks are static/protocol proof only until Golden Era frames advance under a fresh bridge.

- static decomp evidence for exact type/member/method identity

- fail-closed implementation with one route
- runtime proof on Golden Era
- post-action state confirmation from `ai_observe`
- `AGENTS.md` breadcrumb updated from source-prepared to proven

If a proof attempt fails, the agent continues investigating another native-friendly route. It must not expose a partial command or substitute a broader fallback.
