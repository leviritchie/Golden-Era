## 3. Plugin work

All new files go in `Heroes of Might & Magic Olden Era Playtest/OfflineUnlockMod/`.

1. **Town building reader** (new `Homm3TownBuildingReader.cs`). It answers "does this side own a town of faction F with building SID at level ≥ N" and "which buildings does this city have". It reuses `Homm3ConstructionNativeAdapter.TryReadBuildingIdentity` / `TryResolveBuildingsDataFromCityContext`, and returns a per-day cache keyed by side id. No gameplay reader like this exists today (`Homm3StrongholdTownLayers.IsBuildingConstructed` is visual-only). Risk: low to medium. It must run only on the main thread (IL2CPP objects off-thread caused GC fatals before), and it must invalidate on construction and on capture.
2. **Siege-defence town bonus** (new `Homm3TownSiegeDefenseBuildingRuntime.cs`; shared with the Rampart Fountain and the Tower Skyship). Prefix and finalizer on `BattleLogic.Init(int, TransferBattle, bool, bool)`, using the `GameSymbols.DraconicDominion.*` symbols that `Homm3BattleStartMoraleLawRuntime` already resolves. Siege test: `transferBattle.arenaLogicSid` contains "siege" (as in `Homm3CastleEliteStrategemRuntime.cs:269`). It resolves the defended city, reads its buildings through hook 1, and adds the stat to the defender's `TransferHero` `HeroStat` with snapshot/restore. Risk: medium. (a) A garrison with no hero (`Type_Garnison` / `Type_Squad`) has no TransferHero to edit; HoMM3 still gives those troops the bonus, so it needs a squad-level path or the limitation must be stated. (b) It must find the defended town from `TransferBattle`; check that the field exists before building. (c) It must stack correctly with the morale law prefix already on the same method; order both patches explicitly.
3. **Town-visit hero buff (Stables)**, in the same new file as hook 6 or in `Homm3TownBuildingReader.cs`. Postfix on the base virtual `Building.HeroVisit` (`BuildingBank` does not override it), filtered to `Build_Stables`. It adds the vanilla `stable_buff` with `UntilNextWeek` duration, skipping heroes that already have it. Risk: low to medium. The postfix sees every building visit, so it must exit early on the SID. Pick the duration enum from the vanilla stables bank so the weekly reset is native.
4. **Daily side buff (Signal Beacon)**. A side-logic `OnStartDay` postfix (the pattern from `Homm3FactoryLogisticsRuntime.cs`) adds or removes `homm3_signal_beacon_buff` with `BuffDuration(EBuffDurationType.Infinite, -1)` on each of the side's heroes (as `Homm3CoveTreasureSubskills.SetBuff` does). It also runs on hero hire and town capture. Risk: low. A hero hired mid-day gets the buff only on the next day unless the hire is hooked too.

## 4. Owner decisions

1. **Where the Stables lives.** (a) Make `Build_Bank` the real economy Bank and add a separate `Build_Stables` row. (b) Keep both effects on `Build_Bank`: 1000 gold plus the visit buff, with no new row or art. **Recommend (a).** Every vanilla city has a plain Bank, and (b) keeps a donor-shaped merged building.
2. **Signal Beacon (Lighthouse).** Build the land-safe "+10% movement for all your heroes while you own this town", or drop the Lighthouse entirely, since its source cannot exist. **Recommend building it.** It keeps the Castle's mobility theme and costs one small hook that the Stables hook mostly shares.
3. **Colossus resources.** Replace the five daily resources with +2 Morale for all heroes, or add the Morale on top of them. **Recommend replacing them.** The resources were the Lighthouse substitute, and the HoMM3 Colossus has no resource income; adding both would make it the strongest grail in the port.
