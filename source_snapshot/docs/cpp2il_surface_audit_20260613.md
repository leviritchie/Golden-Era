# Cpp2IL Surface Audit - June 13, 2026

This document tracks a static Cpp2IL review of every mod surface currently centralized through `GameSymbols`. The goal is to use the readable Cpp2IL pipeline to confirm, falsify, or improve our deobf assumptions without changing mod behavior during the audit.

Static Cpp2IL evidence can validate field/method names, type relationships, and native object shapes. It cannot by itself prove live Unity scene state, pooled object behavior, rendering state, or whether a hook is safe to invoke at runtime. Recommendations below distinguish symbol fixes from runtime-proof work.

Status key:

- `Verified`: Cpp2IL directly supports the current surface.
- `Drift`: Cpp2IL shows stale or missing symbols that can affect behavior.
- `Partial`: Cpp2IL supports some assumptions but the surface still needs a narrower read or live proof.
- `Risk`: the current approach may be fragile, hot-path unsafe, or too broad.
- `Pending`: inventoried but not yet read in detail.

## Summary So Far

1. `HeroMap` had a concrete symbol drift affecting the adventure-map hero sprite replacement path. The current native visual root field is `cibn`; `GameSymbols.HeroMap.RootGameObjectProperties` has been updated with the Cpp2IL-supported aliases, but runtime proof is still pending.
2. The selected-unit battle HUD surface has multiple current-name gaps. Existing shape fallbacks likely save parts of the path, but the centralized symbol lists should still be updated to reduce ambiguity and startup/runtime probing.
3. Only narrow centralized symbol updates have been made from this audit so far; behavior remains gated where the owning hook was already gated.
