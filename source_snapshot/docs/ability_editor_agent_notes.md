# Ability Editor Agent Notes

- Existing ability/passive edits with no replacement effect are still meaningful. The release overlay generator must apply their display text/icon changes, and active ability rows should also preserve cost/cooldown/rank edits without replacing the underlying mechanic.
- Ability icon keys saved by the editor must be runtime sprite keys, not localization keys or atlas labels such as `Orientation@4x`. If a selected vanilla key relies on runtime UI fallback rendering, add the exact key to the narrow ability-icon allowlist instead of broadening the resolver to arbitrary strings.
- The local editor save validators are intentionally schema-preserving. Unit saves must retain design-contract fields such as `branchRole`, `sourceMechanicId`, and `decisionTest`; hero saves must retain current specialization bonus rows such as `unitStat`, `cityUnitsIncrement`, `heroMagicReplace`, `battleSubskillBonus`, `sideRes`, and metadata like `changeDisposition` / `sourceSpecialtyKey`. Do not restore the older heroStat-only validator or a whitelist that strips unknown-but-generator-owned fields.
- Law tree edits saved by the local editor live under `custom_factions/law_overrides/*.json` and are consumed by `tools/release_port/apply_release_core_overlay.py` when generating `DB/fractions_laws/*` rows and `Lang/english/texts/factionLaws.json`. Keep law effect rows explicit, generator-supported, and editable through structured controls rather than a raw JSON textarea; if a current law bonus shape cannot round-trip through the UI, extend the law editor and validator instead of asking users to hand-edit JSON. The icon browser must keep current law runtime icon keys searchable even when no local PNG preview exists.
- Law icons may be creature runtime SIDs such as `h3_pikeman`, not only `fraction_law_*_icon` sprite keys. Keep `OfflineUnlockMod/homm3_portraits` indexed in the ability editor icon catalog so unit-SID law icons can show previews and be found by search.
- The Laws sidebar must render thumbnail previews with the same effective icon resolver used by the selected-law editor: use `override.iconKey` only when the law override is enabled, otherwise use `law.icon`. Do not let the list fall back to filename initials while the selected editor or icon picker can resolve a real PNG.
- Law effect controls should not require users to memorize custom SIDs. Unit and faction references in the law editor should be picker/dropdown driven from `custom_factions/*.json`, with readable labels shown while still saving the generator-owned SID values.
- The ability editor's current-data panel must read custom unit rows from the patched Golden Era install Core first: `V:\SteamLibrary\steamapps\common\Heroes of Might and Magic Olden Era - Golden Era\HeroesOldenEra_Data\StreamingAssets\Core.zip`. The stock game `Core.zip` has no `DB/units/units_logics/homm3_*` rows, so using it makes every non-materialized custom faction appear to have no abilities.
- Manifest unit lists must honor per-line `variantSids`. Rampart and other source-exact manifests intentionally use names such as `h3_battle_dwarf` instead of synthetic `h3_dwarf_upg`; rebuilding browser rows by suffix alone points the editor at missing Core members.
