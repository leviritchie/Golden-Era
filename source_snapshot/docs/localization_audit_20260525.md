## Tooling Findings

- `tools/release_port/multilingual_custom_lang.py` now repairs missing rows, placeholder drift, and substantive localized custom rows whose text is still exactly English.
- Translation memory is reused only when it preserves placeholder parity. This prevents stale native-memory rows with different `{n}` sets from blocking phrasebook translations and falling back to English.
- Phrasebook loading supports explicit `matchType: "template"`, explicit `matchType: "exact"`, and legacy placeholder-template rows with no `matchType`. Do not add duplicate exact/template entries for the same English text; it makes the intended matching contract ambiguous.
- `tools/release_port/sync_multilingual_custom_lang.py --audit` is dry-run only and reports missing rows, placeholder mismatches, and same-as-English substantive rows after applying the candidate overlay in memory.
- `tools/release_port/sync_multilingual_custom_lang.py` now defaults to the live Steam Golden Era Core path when present, falling back to `analyze_core_overlay.DEFAULT_RELEASE_CORE`.
- `experiments/homm3_tower/generated_core_overlay/Lang` currently contains only `english`; the generated overlay is not self-contained for multilingual review.
- Phrasebook quality checks should include placeholder parity, Russian/Ukrainian Cyrillic coverage, and mojibake markers such as UTF-8 decoded as Windows-1252 (`Ã`, `Â`, `Ä›`, `Å‘`). Several mini-agent drafts contained transliterated Russian/Ukrainian or mojibake and had to be corrected before the audit reached zero.
