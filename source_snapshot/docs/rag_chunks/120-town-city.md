# RAG Chunk: olden-era-playtest/120-town-city

City backdrops are applied by `ModActions.ApplyCustomCityBackdrop()` under `CanvasCityPanel`. Grove and HoMM3 Stronghold PNG backdrops work. Do not lift or reorder global `CanvasTechHUDPanel` while fixing city backdrop layering; `BhHUDSession.me` points at `CanvasTechHUDPanel`, and treating it as a city menu canvas can make the right-side adventure HUD hero/town buttons disappear or become covered after initialization or city UI transitions. HoMM3 Stronghold uses `homm3StrongholdTownBackdropScale` (default `1.18`) to scale the padded city plate/layer root from the top-left origin, reducing right/bottom black padding without overrunning the left/top content edge.

Stronghold building layers are in `Homm3StrongholdTownLayers.cs`, sourced from `homm3_runtime_assets/town_scene_refs/homm3_stronghold/layers/`, and synced through city/building UI hooks. `positions.json` controls placement and is now keyed by named VCMI base `config/factions/stronghold.json` structures instead of replacement-mod numeric indices. Runtime placement lookup prefers `layerId_<level>`, then `layerId_lvl<level>`, then base `layerId`, so upgrade PNGs with different dimensions can have independent x/y rows. Base placement rows must use base/level-1 sprites; if a base row overrides to `*_2.png`, upgraded/high-level art appears before the low-level building is constructed. Upgrade rows copied from a base row must keep the visual footprint grounded with `upgradeY = baseY + baseHeight - upgradeHeight`; reusing the same top-left `y` top-aligns taller upgrades and makes them sit too low. Historical layer IDs are misleading: `wall_1.png` is blacksmith art, `treasury.png` plus `wall_2.png`/`wall_3.png` are fortifications, `spyNetwork.png` is Hall of Valhalla, `lyceum.png` is grail art, and `horde1.png` is the Mess Hall/horde visual. The placement editor previews the full padded 1920x1080 backdrop; use its `--panel WxH` option with the runtime `CanvasCityPanel basis` log when game/editor alignment drifts, and use `Add selected sprite as layer` to create draggable upgrade rows. Runtime layers use per-axis scaling and follow F8 backdrop offset/scale adjustments. `building_layer_map.json` controls building SID -> visual layer mapping, so use the GUI from `python tools/remap_stronghold_town_layers.py` or the script's CLI flags to reorder which constructed building shows each Stronghold sprite/animation; the GUI shows English in-game building names and selected-layer sprite thumbnails next to raw SIDs as read-only aids. If building identities/SIDs are wrong, fix the city generator/data first rather than swapping localization names. Runtime sprite lookup must prefer level-specific PNGs before base `layerId.png`, or animated/leveled buildings such as `extraCapitol_1` get a wrong-sized rect. Additional layers are not reliable yet; asset/layer gaps are suspected.

Release note, May 4 2026: if the release town screen shows the custom backdrop but no Stronghold building layers, first verify the `BuildingsData` aggregate list mapping. Released `Hex.Session.Data.BuildingsData` uses `cnvk` for the public `List<BuildingData>` getter and `chps` for the backing field; old playtest methods `cgtl/cmzg/bfht` are legacy fallbacks. `BuildingData.sid`, `level`, and `isConstructed` still exist in the released interop. Do not treat this symptom as missing PNG assets when the log says placements and `building_layer_map.json` loaded.

Town-screen building click/hover targets are separate from the Stronghold `RawImage` visual layers. The layer images intentionally set `raycastTarget=false`, so changing only those visuals cannot fix clickability. The live IL2CPP dump shows `Hex.UI.City.BhBuildingView : MonoBehaviour, IPointerEnterHandler, IPointerExitHandler, IPointerDownHandler`, but May 2026 testing proved that remapping the native `BhBuildingView` root/`rect` transforms is unsafe: those transforms are visible construction/building-tree UI, and moving them onto town coordinates makes constructed nodes disappear while blue button rectangles appear over the town. Do not revive root/rect remapping or the earlier top-canvas/proxy/extra-`GraphicRaycaster` approach; both regressed performance or UI behavior. A future click solution needs a truly hit-only native child, or a native building action/screen API that can be invoked without moving construction UI.

World-map Stronghold town billboard is `Homm3StrongholdTownMapBillboard.cs`, using `homm3_runtime_assets/map_object_refs/homm3_stronghold_city/avcstrc0.dir/00_00.png`, map object lifecycle hooks, and sanitized `Hex/Lit`.

Stronghold city music uses `Homm3StrongholdCityMusic.cs` and routes to `sounds/city/music/homm3_stronghold`.
