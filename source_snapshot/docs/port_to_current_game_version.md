### What changed in 25509697 (static evidence)

- **No modder tooling.** There is still no mod loader, plugin API or `Mods`/`Modding` type in the
  metadata, and no new modding file in the install. The one new data-authoring surface is the random
  map generator (below).
- **RMG rewrite.** `Hex.MapGenerator.RandomMapTemplate` (and its nested types) is gone, replaced by
  `RmgTemplate` + `RmgSchema` (`ConditionalParam`, `ZoneBiomeRule`, `MainObjectFactionRule`, ...),
  `RmgSchemaSettings`, `MapDescriptionFromRmgSchema`/`...FromRmgTemplate`, `SpawnInfo`, `GlobalBans`,
  `MandatoryContentConfig`. A new base schema `StreamingAssets/map_schemas/Default.mrmg.json` (1.2 MB,
  "Base Template params") holds the zone layouts/defaults that templates now override. Every
  `.rmg.json` template gained `descBlocks`, `maxAlliancesCount` and `spawnInfos[]`
  (`spawn`, `allianceIndex`, `isAllianceLocked`); five new templates (Countdown, Horns, Mayhem,
  Syndicate, Three of a Kind); Core gained `generator/generator_schema_debug_start.json` and nine
  template content pools. The plugin does not reference `RandomMapTemplate`;
  `tools/install_homecoming_rmg_template.py` authors `.rmg.json` and must be re-checked against the new
  fields before its next use.
- **New in-game "custom template" screen** (`Hex.UI.CustomTemplate`: map size, players, symmetry,
  difficulty, heroes, win conditions, tournament, battle day, final battle) and map preview blocks
  (`Hex.UI.MapPreview`).
- **Alliances.** `Hex.UI.Alliances` (resource ask/send, notifications), `Hex.Configs.AllianceConfig`,
  `Hex.MapEditor.BhAlliancesSettings`, `DB/alliences/alliances.json`.
- Save/load UI (`Hex.UI.SaveLoad`, `Hex.SaveLoad.JsonSessionInfo`), emotion wheel, lobby low-priority
  queue.
- Types: 228 new and 50 gone real-name types against 25061458 (list:
  `F:\olden_port_work\new_types_25509697.txt`). Core: 12 members added, 0 removed, 392 changed
  (`artifacts/port_current/core_diff_25061458_25509697.json`). Maps: 11 vanilla `.map` files changed;
  183 non-template install files changed (levels, sharedassets, resources).

Rule learned in run 9: **never add golden literals to a `GameSymbols.cs` symbol while porting.** It changes the

a different live name, as `EsceneSceneLoad` does for live `PDM_3`. A `null` slot becomes the
`!unresolved-on-current-build:` sentinel.

## 2. IL2CPP drift

**Method (generated artifact validated).** `interopgen` runs Cpp2IL, then Il2CppInterop, with
BepInEx's settings (`UnhollowerDeobfuscationRegex = ^[a-z]{2}$|^[a-z]{3}$|^[a-c][a-z]{3}$`). I
calibrated it by regenerating Golden Era interop from the stock Golden Era binaries. The resulting
type/member/signature index is **identical** to the installed `BepInEx/interop` index across all
296,148 rows. The live interop was then generated the same way, without touching the live
install.

**Compile-time references.** `VerifyPluginLiveInteropRefs` checked the deployed plugin DLL against
`interop_live`. It found 1172 member refs and 11 findings: the 10 already allow-listed, plus **1
new**. `Hex.UI.BhHeroAbilitiesView` moved to `Hex.UI.Battle.BhHeroAbilitiesView`; it is used by
`Homm3WarcriesHeroAbilityHook::PatchHeroRefreshDiagnostics`. The compile-time surface is small
because nearly all game access goes by string through `GameSymbols.cs`: 3085 `GameSymbols.` uses,
280 `.Patch(` calls, 63 `[HarmonyPatch]`, and 260 `AccessTools` lookups.

**Namespaced (real-name) types are stable.**
- 3277 Golden Era types → 3080 (94%) keep the same full name in the live build, and 2359 (72%) keep identical member-name sets.
- 94% of their members (94,257 / 100,278) survive by name.
- 197 namespaced types are gone or moved; the plugin mentions none of them except the one moved type above.
- 269 are new. These include Arena reroll/rewards, `ObjGladiatorSpire`, `BhSimulatedBattle`, and win-condition notifications.

**Obfuscated and generated names are almost entirely reshuffled.**
- Global-namespace types: 4234 in Golden Era, 4310 in live. Only 422 (10%) share a name, and 264 of those have identical members.
- Every type referenced by a `GameSymbols.cs` literal was checked for same owner and same shape. Results:
  - **Raw obfuscated type names:** 4 still mean the same type. **163 now name a different type (same name, different shape)**, and 31 are gone.
  - **Il2CppInterop signature-derived type names** (`ObjectPublic...Unique`): 3 survive and 66 are gone. These names embed obfuscated field-type abbreviations, so they are **not** stable across this update either.
  - **Generated member names:** 263 survive on the same owner with the same signature. Most are low-information ordinals such as `field_Public_String_0`. 153 now sit on other types, and 128 are gone.
- In hint groups, 748 GameSymbols groups resolve through an obfuscated or generated name on Golden Era. 125 of those find nothing on live. Most of the other 623 match only because an old name was **reused for a different class**.

**Consequence.** The current resolvers take the first matching hint name. For example,
`ResolveFirstType` in `Homm3AdventureVisionLawDiagnostics.cs` calls `GameMember.FindType` and then
`AccessTools.TypeByName`. Loaded on the live build, this would **silently bind to the wrong classes**
for most obfuscated hints, which breaks AGENTS.md's fail-closed rule. Appending new names to the
hint arrays is not safe. The old names must be removed, or scoped to the build they came from.

**Automatic remap is feasible (generated artifact validated).**
- `match_types.py` fingerprints each type by assembly, normalised base type, and member kinds with
  signatures, where obfuscated or generated type tokens become placeholders or already-matched ids.
  Iterated exact matching uniquely pairs **1056 / 4234 (25%)** global types.
- `order_probe.py` shows that obfuscated names are **assigned in stable order**. Of 580 unique
  anchor pairs (for example `cpw→cqn`, `cty→cvm`, `fqn→ftk`), **99.3% are monotone**; the median
  rank shift is +6.
- An anchor-plus-monotone-alignment matcher can therefore place most of the remaining types between
  the exact anchors. It needs fuzzy scoring only inside each gap. This is the same insight behind
  the May hotfix tool `tools/map_obfuscation.py` (structural fingerprint plus Levenshtein, 97.5%
  match), but that tool works on Il2CppDumper `dump.cs`. The index here comes from the same
  interop BepInEx will load.
- Member-level remap is not measured yet. The first probe had too few same-signature anchors on
  namespaced types. Members should be matched inside matched owner types by normalised signature
  and declaration ordinal.

**Type matching** (per assembly, iterated to a fixed point):
1. Stable-name seeds: a whole native path of real names.
2. Exact fingerprints: kind, arity, base, interfaces, parent, compiler-generated stem, and the

3. A weighted monotone chain over declaration ordinal.
4. Inside each gap of the chain, an order-preserving DP over a structural similarity. A pair
   needs score >= 0.60 and a margin of >= 0.08 against its best in-gap alternative.
   Structurally identical twins pair by order only when both sides hold the same count (0.8).

**Member matching** inside a matched owner, per field/method/prop/const:

GameAssembly and metadata sha256, and the remap refuses a TSV whose shas do not match `inputs.json`.
Function bounds come from `.pdata`, and capstone disassembles each body. A body's features are:
- string literals and callees by name (metadata-usage tokens, decoded as

loop cap. So choose the copy that Golden Era binds by its role (the caller, the call position, or the
in-order name), never by body score alone. Patching one copy does not patch the others.

**Sea movement cost vs vanilla (2026-10-01, static only, no runtime test).**
- Movement code: the mono demo `Hex.dll` (`Heroes of Might & Magic Olden Era Demo`, ilspycmd,
  scratch `V:\olden_port_work\sea_cost_research`) is source/static evidence.
  - `GroundPathfinder.MoveCost` and `WorldHero` both call `Formulas.CalculateMoveCost(
    pathmap.GetPenalty(node), roadBonus, diagonal, IsUnitsHaveNativeBiomeForNode(node),
    landscapePenaltyPerBonus, roadPerBonus)`. The formula is
    `max(3, 10 * (diagonal ? 1.41 : 1) * (1 + nonNative * penalty * (1 + landscapePenaltyPerBonus)) * (1 - road...))`.
  - `Pathmap.GetPenalty` returns the river penalty when a river covers the node, else
    `TileConfig.penalty` of the node's tile (`Map.RebuildPathmap`). It never reads `waterMap`.
  - `WaterConfig` has only `name`, `material` and `testing`, and has no movement field. The live
    25509697 interop has the same `TileConfig` (name, penalty, biome, testing) and `WaterConfig`
    (name, material, testing) shapes. The live bodies are obfuscated native code, so the formula on
    live is mono parity, not a live disassembly.
- Vanilla has no boat travel. The 25509697 vanilla Core has no boat, shipyard or sail rows, and
  `DB/map/waters/waters.json` holds only the seven materials. Vanilla water is a visual material
  over a `levelsMap` -1 basin, and the generator marks lakes `ObstacleState.Water`. So there is no
  native boat movement cost to match.
- Vanilla seabeds vary. A survey of the 25509697 native maps (water cells as
  (tile, waterMap, level)) shows that every water cell sits at level -1, on whatever land tile
  the author painted:
  - Glittering Strait `water_2`: Grass 1246, Sand 792, Dirt 38, Autumn 29, Lava 9;
  - `Story_maps/t_C7`: Sand 459 (all of it);
  - The Mysterious Island `water_7`: Grass 43233, Sand 649, and others;
  - Broken Alliance `water_7`: Grass 1500, Sand 21.

  Grass (0.4) is the most common seabed and Sand (0.8) the second.
- Result: 0.8 is native behaviour. The engine charges the seabed tile's penalty, exactly as it
  does under vanilla water. No vanilla faction or hero is Sand-native, so every army pays it.
  Only `anyLandEqualNativeBiome` bonuses waive it, and they waived tile 18 as well.
- What changed for the mod's own design: an orthogonal step onto ocean costs 18 MP (Sand) instead
  of 40 (tile 18 at 3.0), before Pathfinding. The traversal bridge's water-start relief
  (`landscapePenaltyPerBonus` -> -1, which makes a step cost 10) is unchanged. Only the boarding day
  is cheaper. HoMM3 itself charges sea tiles the base cost, and boarding ends the day.
- Not changed. Options if the boarding-day cost should go back to 3.0, each needing a user
  decision:
  1. a dedicated seabed `TileConfig` (Sand biome and visuals, penalty 3.0). This reintroduces a
     mod tile id, which is what option (b) removed;
  2. a plugin cost hook, which goes against the native-first rule;
  3. keep 0.8 (recommended: native semantics, and closer to HoMM3 per-tile sea cost).

  **Decided 2026-10-01 (user): keep 0.8.** No seabed tile and no cost hook.
