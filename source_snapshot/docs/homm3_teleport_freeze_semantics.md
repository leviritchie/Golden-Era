# Devil teleport freeze semantics

The freeze gate still refuses a pose held for three or more moving DEF frames. For the pinned teleport clips it also counts the Hips collapse scale as pose motion; unrelated scale noise cannot reset a nonteleporter's held-pose run. The devil-family body is authored to shrink to 0.001 under the teleport fire cloud. Changing cloud pixels are not evidence that the hidden body should articulate.

## Source evidence

`tools/homm3_def_retarget/ext/inferno_teleport.py` freezes the captured pose under the burst and collapses the body at `teleport.out[2]`, then grows it from the first visible frame `teleport.in[1]`. Each of `h3_devil`, `h3_arch_devil`, and `h3_arch_demon` declares `out = [MoveStart, 4, 7]` and `in = [MoveEnd, 5, 8]`. Their DEF Move is one frame; MoveStart and MoveEnd carry the teleport.

The [source contact sheet](../tools/homm3_def_retarget_delivery/reference/teleport_effect_source_sheet.png) shows every proposed hidden window: MoveStart frames 7-13 and MoveEnd frames 0-4, across all three units. These frames are fire-cloud dominant; no articulated body is discernible. A weapon tip remains visible in some boundary frames, so this is a **body-obscured** classification, not a claim that every source pixel is an effect or that the effect delivery looks correct. The independently authored `inferno_fx_masks.py` `opaque_all` masks equal each source frame's fully opaque pixels. That equality alone does not classify flesh; the contact-sheet review and the authored collapse bounds are also required.

`reference/teleport_effect_windows.json` pins each unit's exact DEF group, window, source-PNG set SHA-256, effect-mask set SHA-256, and source cadence. The digest of a set is SHA-256 of the concatenated lowercase per-file SHA-256 hex strings in frame order. `teleport_effect_windows()` checks the source files against the master-sequence hashes, mask content against the source's opaque pixels, the declared teleport bounds, and the one-frame DEF Move. Missing or changed evidence fails closed. The normal-build articulation validator checks all reference rows, including units not yet frozen.

## Delivery gate

For a held step to be excused, both endpoints must fall inside a pinned cloud window on the exact DEF key-time grid **and** the GLB must show the skinned body collapsed at or below 0.0011 on both endpoints. The gate audits every mesh's skin weights: each vertex must have complete weights and every weighted joint must be under the animated Hips subtree. Ancestor/descendant and mesh-node scales must not expand the collapsed body; inverse bind matrices must not amplify it, and static matrix transforms are refused rather than guessed. Audited scale tracks must have finite, increasing keys and either LINEAR or STEP glTF interpolation; the gate evaluates each mode as authored and refuses CUBICSPLINE or unknown modes. An uncollapsed body or prop cannot borrow a Hips scale stamp. A missing scale curve, source pin, mask, or skin audit is a refusal, not a strict-to-permissive fallback. Holds outside the windows remain subject to the original run limit.

Focused source checks and synthetic negatives are in `test_flyer_articulation_freeze.py`. On the current canonical GLBs, all three devil-family freeze reports pass this source-relative rule; before the change they failed only MoveStart/MoveEnd cloud holds. This is generated-artifact validation, not a frozen selection, native-style VFX approval, installed payload, or gameplay proof. In particular, the current `defFlipbook` look specs do not satisfy the user-requested Olden Era-native effect presentation on their own.

## Measured DEF states (2026-09-27)

The gate's rule is "a held pose while the DEF moves", so the DEF's motion is measured on its shape, not on its whole-frame RGBA hash. A source frame's body is its non-shadow silhouette: alpha == 255 (the extraction draws the HoMM3 shadow indices as black at alpha 64/128; palette cycling and glyph shimmer change colour, not alpha). Two measured states excuse a held mesh step, by one rule for every unit; there is no per-unit list, and holds outside them keep the original run limit (`FREEZE_RUN_MAX`).

- **DEF hold.** A run of held mesh steps is excused when every pair of its DEF frames has silhouettes within `DEF_HOLD_PX` = 1.4143 px (symmetric Hausdorff distance, i.e. one pixel including the diagonal). Hash-identical frames are the zero case. Evidence: `h3_enchanter` Mouseover frames 2-8 change 1660 px of colour per step, but their silhouettes alternate between two states with 53 px of contour dither and spread exactly 1.414 px; its ShootFront frames 4-6 (robe sweep, arms) spread 33.6 px, and the devil-family teleport cloud windows at least 18.0 px over any three frames. Over the 79 frozen deliveries, the non-identical three-frame windows spread 1.0 px (253 windows, all Idle or Mouseover dither), 1.414 (66), 2.0 (52), 2.236 (30), then upward. **Margin, stated plainly:** the cutoff sits at the sprite's pixel quantum, one step below the next measured value (2.0 px); it also classes one-pixel Idle breathing as a hold, so a mesh that stalls over a sub-2-px idle DEF passes. Real limb motion is an order of magnitude above it. On the frozen fleet this measure changes exactly one result: the enchanter Mouseover (freezeRun 4 -> 1, 3 steps excused).
- **DEF body absent.** A frame whose silhouette above the unit's ground band (rows above the lowest `DEF_GROUND_BAND` = 25% of the Idle frame 0 body height) is at most `DEF_ABSENT_FRAC` = 0.5% of Idle frame 0's has no body left: only a floor-level effect or ripple remains. A held step between two such frames is excused **only** with the teleport collapse proof: the skin audit (`hidden_body_root`), an animated Hips scale at or below 0.0011 at both frames, and no expanding scale in the hierarchy. A visible mesh while the DEF body is absent stays a fault, and a still ripple cannot excuse it through the DEF-hold rule. An audit failure is named in the fault. Evidence: `hota_cove_oceanid` MoveStart frames 6-12 and MoveEnd frames 0-6 (the dive into the water ripple) measure 0 px above the band; over the frozen fleet every absent frame measures 0 and the lowest present frame is 1.27% (`hota_cove_tidecaller` Death frame 6), so a lying corpse is still a body. On the frozen fleet this changes exactly the oceanid MoveStart/MoveEnd (freezeRun 6/7 -> 1, collapsed at 0.001).

The devil-family cloud windows measure neither state (their clouds are opaque above the ground band and move), so they stay on the pinned-window rule above. Tests: `DefShapeFreezeTest` in `test_flyer_articulation_freeze.py` (synthetic positives and negatives, plus the real enchanter, oceanid and devil source frames). Proof tier: generated-artifact validation.
